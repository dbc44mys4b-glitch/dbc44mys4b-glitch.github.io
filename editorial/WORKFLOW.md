# Редакционный процесс BucharestUA

При ручном запуске готовим до пяти SEO-гидов или городских статей и дополнительно одну–две актуальные новости в день по времени Бухареста. Темп зависит от качества источников и изображений. Каждый материал выходит после одобрения владельцем конкретной версии. Новый текст и обновление уже опубликованной страницы проходят одинаковый путь.

## 1. Подготовить и проверить

Скопируйте [единый JSON-шаблон](templates/article.json) в закрытое рабочее пространство в папку `<slug>/draft.json`. Сохраните рядом обложку. Для гида заполните минимум три содержательных раздела. Для новости выберите `type: news`, добавьте `event_date` в формате `ГГГГ-ММ-ДД` и `event_context` с пояснением для жителей. Достаточно одного содержательного раздела, если он раскрывает, что произошло. Первый источник новости ведёт напрямую на первоисточник сообщения или события. Для обновления сохраните исходный `publish_date` и добавьте `date_modified`.

Перед отправкой один раз проверьте материал целиком.

- Сверьте даты, адреса, суммы, часы, условия и другие меняющиеся сведения с актуальными первоисточниками. Для новостей укажите, что произошло, когда, где и кого это касается. Пишите своими словами. Ссылайтесь на оригинальное сообщение и дополнительные источники, когда они нужны для проверки. Соблюдайте права на текст и фотографии источника.
- Подберите детализированную горизонтальную JPEG или PNG от 1200 × 630 до 4 МБ. Проверьте реальное содержание кадра, кадрирование и alt-текст. Сохраните сведения о правах рядом с черновиком. Если фото иллюстративное, укажите `illustrative: true`. При обработке добавьте `changes` с описанием, например «Кадрировано». Проверьте, что лицензия допускает обработку и обрезку в карточках.
- Откройте предпросмотр на телефоне и широком экране. Проверьте заголовок, видимость обложки, текст, ссылки, карточку для соцсетей и ссылку на городской Telegram. Команда предпросмотра проверяет метаданные, канонический URL, структуру, локальные ссылки и атрибуцию. Названия, описание и лид должны отвечать на реальный запрос читателя.

| Происхождение | Обложка | Что записать в `cover` помимо `author` и `alt` |
| --- | --- | --- |
| Собственное изображение | JPEG | `kind: original`, `provenance` с данными оригинала и права на выпуск |
| Wikimedia Commons | JPEG | `kind: photo`, `license`, `license_url`, `source_url`, `commons_title` |
| Другая лицензия или разрешение | JPEG | `kind: licensed`, `source_url`, `license` и `license_url` для поддерживаемой открытой лицензии либо `permission` со ссылкой или ID конкретного разрешения. Учтите обязательный кредит и условия обработки. |
| AI-иллюстрация | PNG | `kind: ai_illustration`, `author: BucharestUA`, `provenance` с инструментом и условиями использования. На странице автоматически появится пометка «AI-иллюстрация BucharestUA». Такой кадр не используем как документальное фото события. |

## 2. Отправить владельцу

В командах ниже `/private/queue` обозначает вашу закрытую рабочую папку вне публичного репозитория. Для каждого материала используйте свой `<slug>`, а для новой версии — следующий каталог `preview-N`.

```sh
python3 scripts/publish_queue.py preview /private/queue/<slug>/draft.json \
  --output /private/queue/<slug>/preview-1
python3 scripts/publish_queue.py status --workspace /private/queue
```

Отправьте владельцу по одному сообщению на материал. Включите полный текст с обложкой или доступный ему закрытый предпросмотр, дату фактчекинга, ссылки на источники, кредит и права на обложку, slug и полный идентификатор версии из команды. Владелец отвечает «Одобряю» на сообщение с этой версией либо перечисляет правки. Любое изменение текста, изображения или оформления, меняющее версию, требует нового предпросмотра и одобрения. При отсутствии явного ответа состояние остаётся «На согласовании».

## 3. Выпустить и проверить

После явного ответа владельца используйте ссылку или ID именно этого сообщения. Обновите рабочую копию до актуального `main`, чтобы не перезаписать соседние релизы. Выполните команду с новым каталогом выпуска.

```sh
python3 scripts/publish_queue.py publish /private/queue/<slug>/draft.json \
  --preview /private/queue/<slug>/preview-1 \
  --approved '<полная версия из одобренного предпросмотра>' \
  --approval-ref '<ID или ссылка на явное согласие владельца>' \
  --output /private/queue/<slug>/release-1
```

Команда сверяет подготовленную версию с предпросмотром и создаёт локальный пакет. В частном `approval.json` хранится ссылка или ID решения. В публичной записи выпуска хранится только отпечаток этого идентификатора. Согласие проверяет редактор в чате. Скопируйте в `main` только файлы из пакета выпуска, зафиксируйте их одним коммитом и дождитесь деплоя GitHub Pages. Для следующего материала начните с этого обновлённого `main`.

```sh
python3 scripts/publish_queue.py verify <slug>
```

Команда проверяет HTTP 200 и содержимое публичной страницы и обложки, а также наличие URL в sitemap. Если Python требует отдельный набор доверенных сертификатов, передайте его через `--ca-file`. Проверьте карточку в каталоге и на главной, затем отправьте владельцу точный URL и ссылку на коммит. До этой проверки используйте состояние «В main, публичный URL на проверке».
